Redis通关手册（一）：基本数据类型

发表于2026-07-13|更新于2026-07-28|后端
|浏览量:

Redis 是一个数据结构服务器。其核心是提供了一系列原生数据类型，可帮助您解决从缓存、队列到事件处理等各种各样的问题。以下是对常用的数据类型的简要描述，并提供指向更详细概述和命令参考的链接。

Strings

Redis的字符串类型是最基本的数据类型，字符串存储字节序列，包括文本、序列化的对象和二进制数组。它们通常用于缓存，但还支持额外的功能，比如可以使用string实现计数器并执行位运算。

使用 SET 和 GET 命令是我们设置和检索字符串值的方式。请注意，如果键已经存在，即使键关联的是非字符串值， SET 也会替换任何已经存储在键中的值。所以 SET 执行的是赋值操作。

值可以是各种类型的字符串（包括二进制数据），例如你可以在一个值中存储一个 jpeg 图像。值的大小不能超过 512 MB。

INCR 命令将字符串值解析为整数，增加一，并将获得的新值设置为新的值。还有其他类似的命令，如 INCRBY 、 DECR 和 DECRBY 。内部始终是相同的命令，但以稍微不同的方式执行。

INCR的原子性 意味着即即使多个客户端同时对同一个键执行 INCR 操作，也不会进入竞争条件。例如，永远不会发生客户端 1 读取”10”，客户端 2 同时读取”10”，两者都增加到 11，并将新值设置为 11 的情况。最终值总是 12，而读取-增加-设置操作是在所有其他客户端不在执行命令的同时完成的。

Limits

默认情况下，单个 Redis 字符串的最大长度为 512 MB。

基本命令

  • SET 存储一个字符串值。
  • SETNX 仅当键不存在时存储字符串值。用于实现锁。
  • GET 获取一个字符串值。
  • MGET 在一次操作中检索多个字符串值。
  • INCR 原子性地将给定键存储的计数器加 1。
  • INCRBY 原子性地增加（当传递负数时减少）给定键存储的计数器。
  • INCRBYFLOAT 用于浮点计数器的命令

Lists

Redis 列表是由字符串值组成的链表。Redis 列表常用于：

  • 实现栈和队列。
  • 为后台工作系统构建队列管理。

什么是列表？

为了解释列表数据类型，最好先从一点理论开始，因为列表这个词在信息技术人员中经常被错误地使用。例如，“Python 列表”并不像名字暗示的那样（链表），而是数组（在 Ruby 中，这个数据类型实际上也被称为数组）。

从非常一般的角度来看，列表只是一个有序元素的序列：10,20,1,2,3 就是一个列表。但是使用数组实现的列表属性与使用链表实现的列表属性非常不同。

Redis 列表通过链表实现。这意味着即使列表中有数百万个元素，向列表头部或尾部添加新元素的操作也是常数时间。使用 LPUSH 命令向包含十个元素的列表头部添加新元素的速率与向包含一千万个元素的列表头部添加元素的速率相同。

有什么缺点？在用数组实现的列表中，通过索引访问元素非常快（常数时间索引访问），而在用链表实现的列表中则不那么快（操作所需工作量与访问元素的索引成正比）。

Redis 列表使用链表实现，因为对于一个数据库系统来说，能够非常快速地向一个非常长的列表中添加元素至关重要。另一个显著的优点，是 Redis 列表可以在常数时间内以常数长度进行读取。

当快速访问大量元素的中很重要时，可以使用另一种数据结构，称为有序集合。

基本命令

  • LPUSH  向列表头部添加新元素
  • RPUSH  向尾部添加新元素
  • LPOP 从列表头部移除并返回一个元素
  • RPOP 从列表尾部移除并返回一个元素
  • LLEN 返回列表长度
  • LMOVE 原子性地将元素从一个列表移动到另一个列表。
  • LRANGE 从列表中提取一系列元素
  • LTRIM 将列表缩减到指定的元素范围
  • BLPOP  从列表头部移除并返回一个元素。如果列表为空，则命令会阻塞，直到有元素可用或达到指定的超时时间。
  • BLMOVE 原子地将元素从源列表移动到目标列表。如果源列表为空，则命令会阻塞，直到有新元素可用。

对列表的阻塞操作

列表具有一个特殊功能，使它们适合实现队列，并且在一般情况下，作为进程间通信系统的构建块：阻塞操作。

如果你想要用一个进程将数据推入列表，而用另一个进程实际对这些数据进行某种处理。这是常见的生产者/消费者设置，可以以下简单的这种方式实现：

  • 要将数据推入列表，生产者调用 LPUSH 。
  • 要从列表中提取/处理数据，消费者调用 RPOP 。

然而，有时列表可能为空，没有可处理的内容，所以 RPOP 只会返回 NULL。在这种情况下，消费者被迫等待一段时间后，再使用 RPOP 重新尝试。这被称为轮询，在这个上下文中并不是一个好主意，因为它有几个缺点：

  1. 迫使 Redis 和客户端处理无用的命令（当列表为空时，所有请求都不会完成实际工作，它们只会返回 NULL）。
  2. 增加了处理项目的延迟，因为工人在收到 NULL 后会等待一段时间。为了缩短延迟，我们可以在调用 RPOP 之间等待更短的时间，但这会放大问题 1，即更多无用的 Redis 调用。

Redis 实现了名为 BRPOP 和 BLPOP 的命令，它们是 RPOP 和 LPOP 的阻塞版本，能够在列表为空时阻塞：只有当列表中添加了新元素或达到用户指定的超时时间时，才会返回给调用者。

Limits

Redis 列表的最大长度为 2^32 - 1（4,294,967,295）个元素。

性能

列表操作访问头部或尾部的时间复杂度为 O(1)，这意味着它们非常高效。然而，操作列表内部元素的操作通常为 O(n)。这些操作的例子包括 LINDEX 、 LINSERT 和 LSET 。运行这些命令时要小心，尤其是在操作大型列表时。

Sets

Redis 集合是一个无序的唯一字符串（成员）集合。可以使用 Redis 集合高效地：

  • 追踪独特项目（例如，追踪访问特定博客文章的所有唯一 IP 地址）。
  • 表示关系（例如，具有特定角色的所有用户的集合）。
  • 执行常见的集合操作，如交集、并集和差集。

基本命令

  • SADD 向集合中添加新成员。
  • SREM 从集合中删除指定的成员。
  • SISMEMBER 测试字符串是否为集合成员
  • SINTER 返回两个或更多集合共有的成员集合（即交集）
  • SCARD 返回集合的大小（也称为基数）。

Limits

Redis 集合的最大大小为 2^32 - 1（4,294,967,295）个成员。

性能

大多数集合操作，包括添加、删除和检查一个项目是否是集合成员，都是 O(1)的。这意味着它们非常高效。然而，对于拥有数十万或更多成员的大集合，在运行 SMEMBERS 命令时应该谨慎。这个命令是 O(n)的，并且会一次性返回整个集合。作为替代方案，可以考虑使用 SSCAN ，它允许你迭代地检索集合的所有成员。

替代方案

集合在大数据集（或流数据）上的成员资格检查可能会消耗大量内存。如果您担心内存使用，并且不需要完美的精度，可以考虑使用布隆过滤器或布谷鸟过滤器作为集合的替代方案。

Hashes

Redis 哈希表是一种记录类型，结构为字段-值对的集合。可以使用哈希表来表示基本对象，以及存储计数器分组等。

字段过期

Redis 7.4 引入了为单个哈希字段指定过期时间或生存时间（TTL）值的功能。这个功能与键过期类似，包括一系列相似的命令。

使用以下命令设置特定字段的精确过期时间或 TTL 值：

  • HEXPIRE: 设置剩余的 TTL（生存时间）为秒。
  • HPEXPIRE: 设置剩余的 TTL（生存时间）为毫秒。
  • HEXPIREAT: 将过期时间设置为以秒为单位的时间戳。
  • HPEXPIREAT: 将过期时间设置为以毫秒为单位的时间戳。

使用以下命令可以检索特定字段将过期的确切时间或剩余的 TTL：

  • HEXPIRETIME: 以秒为单位获取过期时间的时间戳
  • HPEXPIRETIME: 获取过期时间，以毫秒为时间戳。
  • HTTL: 获取剩余的 TTL（生存时间），以秒为单位。
  • HPTTL: 获取剩余的 TTL，以毫秒为单位

Limits

每个哈希可以存储最多 4,294,967,295（2^32 - 1）个键值对。实际上，你哈希存储限制仅由托管 Redis 部署的虚拟机的总内存决定。

性能

大多数 Redis 哈希命令都是 O(1)。
一些命令，如 HKEYS 、 HVALS 、 HGETALL 以及大多数与过期相关的命令，是 O(n)，其中 n 是键值对的数量。

Sorted sets

Redis 有序集合是一组唯一的字符串（成员），按照与它们关联的分数进行排序。当多个字符串具有相同的分数时，这些字符串将按照字典顺序排序。有序集合的一些用例包括：

  • 排行榜。例如可以使用有序集合轻松维护一个大型在线游戏中最高分数的有序列表。
  • 速率限制器。特别是可以使用有序集合构建一个滑动窗口速率限制器，以防止过多的 API 请求。

你可以将有序集合视为集合和哈希的混合体。像集合一样，有序集合由唯一的、不重复的字符串元素组成，所以在某种程度上，有序集合也是一个集合。

然而，虽然集合内的元素是无序的，但有序集合中的每个元素都与一个浮点值相关联，称为分数（这也是为什么类型也类似于哈希，因为每个元素都映射到一个值）。

此外，有序集合中的元素是按顺序取出的（因此它们不是按请求排序的，顺序是有序集合所使用的数据结构的特性）。它们的排序规则如下：

  • 如果 B 和 A 是两个具有不同分数的元素，那么当 A.score > B.score 时，A > B。
  • 如果 B 和 A 的分数完全相同，那么当 A 字符串在字典序上大于 B 字符串时，A > B。由于有序集合只包含唯一元素，B 和 A 字符串不能相等。

基本命令

  • ZADD 向有序集合中添加新成员及其关联的分数。如果成员已存在，则更新分数。
  • ZRANGE 返回有序集合中给定范围内的成员，并按顺序排序。
  • ZRANK 返回提供的成员的排名，有序集合是升序排列的。
  • ZREVRANK 返回提供的成员的排名，有序集合是降序排列的。

字典序分数

在 Redis 2.8 版本中，引入了一个新功能，允许按字典序获取范围，假设排序集合中的元素都是使用相同的相同分数插入的（元素使用 C memcmp 函数进行比较，因此保证没有排序，每个 Redis 实例都将返回相同的输出）。

操作字典序范围的主要命令是 ZRANGEBYLEX 、 ZREVRANGEBYLEX 、 ZREMRANGEBYLEX 和 ZLEXCOUNT 。

例如，让我们再次添加我们的著名赛车手列表，但这次为所有元素使用零分数。我们会看到，由于排序集合的排序规则，它们已经按字典序排序。使用 ZRANGEBYLEX 我们可以请求字典序范围：

范围可以是包含的或排除的（取决于第一个字符），字符串的无穷大和负无穷大分别用 + 和 - 字符串指定。

这个功能很重要，因为它允许我们将有序集合用作通用索引。例如，如果您想按 128 位无符号整数参数索引元素，您只需将元素添加到具有相同分数（例如 0）的有序集合中，但具有由大端 128 位数字组成的 16 字节前缀。由于大端序号在按字典序（原始字节顺序）排序时实际上是按数值排序的，因此您可以请求 128 位空间内的范围，并获取元素的值，忽略前缀。

性能

大多数有序集合操作的时间复杂度为 O(log(n))，其中 n 是成员数量。

运行带有大返回值（例如，数万或更多）的 ZRANGE 命令时要小心。该命令的时间复杂度为 O(log(n) + m)，其中 m 是返回的结果数量。

替代方案

Redis 有序集合有时用于索引其他 Redis 数据结构。如果需要索引和查询数据，请考虑使用 JSON 数据类型和 Redis 查询引擎功能。
